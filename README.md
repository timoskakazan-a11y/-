# Медиацентр школы №71 (Казань)

Сайт медиацентра: ближайшие мероприятия, фотоархив (ссылки на альбомы ВК)
и свои анонимные формы (как Google/Яндекс Формы), например сбор песен для дискотеки.

**Стек:** Next.js 16 (App Router) · Supabase (PostgreSQL) · Vercel.

## Что внутри

| Адрес | Что это |
|---|---|
| `/` | Главная: ближайшие события и свежие альбомы |
| `/events` | Все предстоящие мероприятия |
| `/albums` | Фотоархив — карточки со ссылками на альбомы ВК |
| `/about` | О медиацентре |
| `/f/<адрес>` | Публичная анонимная форма (эту ссылку и раздаём ученикам) |
| `/admin` | Админка (вход по паролю): формы, ответы, CSV, мероприятия, альбомы |

## Надёжность сбора ответов

- **Ни один ответ не теряется молча.** Ученик видит «Ответ записан» только после
  того, как база подтвердила запись.
- **Нет дублей.** У каждой отправки уникальный токен; повтор (двойной клик,
  обрыв сети) не создаёт вторую запись.
- **Автоповтор.** При плохой связи браузер сам повторяет отправку до 6 раз,
  а без интернета ждёт, пока он появится. Сервер тоже повторяет запрос к БД.
- **Черновик.** Заполненные поля сохраняются в браузере — обновление
  страницы ничего не стирает.
- **Атомарная запись.** Проверка формы, лимитов и вставка — одна транзакция
  в PostgreSQL (функция `submit_form_response`). Лимит «максимум N ответов»
  не превышается даже при сотнях одновременных отправок.
- **Кеш страниц (ISR).** Главная, события и альбомы отдаются из кеша Vercel;
  если база на минуту недоступна, посетители видят последнюю удачную версию.

Проверено: 600 одновременных отправок → 600 записей, 0 потерь;
200 одновременных отправок при лимите 50 → ровно 50 записей.

## Безопасность

- В Supabase включён RLS **без единой политики**: публичный ключ не может
  ни читать, ни писать. Работает только сервер сайта с `service_role` ключом.
- Ответы проверяются на сервере по описанию формы: лишние поля
  отбрасываются, варианты сверяются со списком, длина ограничена.
- Админка: пароль + подписанная httpOnly cookie, проверка и в `proxy.ts`,
  и в каждом серверном действии. Перебор пароля блокируется (8 попыток / 15 мин).
- Анти-спам: скрытое поле-ловушка для ботов, лимит 120 ответов с одного IP
  за 10 минут на форму (с запасом для школьного Wi-Fi, где у всех один IP),
  приём только с собственного домена.
- IP не хранится — только его хеш с секретной солью (анонимность).
- Заголовки безопасности: CSP, запрет встраивания во фреймы, HSTS и др.
- Несуществующие страницы → аккуратная 404; `/admin` без входа → страница логина.
- Экспорт CSV защищён от «формульных» инъекций в Excel.

## Установка

### 1. Supabase
1. Создайте проект на [supabase.com](https://supabase.com) (регион — Europe, например Frankfurt).
2. **SQL Editor → New query** → вставьте содержимое `supabase/schema.sql` → **Run**.
   Скрипт можно запускать повторно — он ничего не сломает.
3. **Project Settings → API**: скопируйте `Project URL` и ключ `service_role`.

### 2. Переменные окружения (Vercel → Project → Settings → Environment Variables)

| Переменная | Значение |
|---|---|
| `SUPABASE_URL` | Project URL из Supabase |
| `SUPABASE_SERVICE_ROLE_KEY` | ключ `service_role` (секретный!) |
| `ADMIN_PASSWORD` | пароль для входа в `/admin` (длинный) |
| `SESSION_SECRET` | случайная строка ≥ 32 символов (`openssl rand -hex 32`) |

После добавления переменных сделайте **Redeploy**.

### 3. Локальный запуск
```bash
cp .env.example .env.local   # заполнить
npm install
npm run dev
```

## Как пользоваться

1. Зайдите на `/admin`, введите пароль.
2. **Формы → Новая форма**: название и адрес (например `disco-new-year`).
3. Добавьте вопросы (короткий/длинный ответ, список, один или несколько вариантов),
   включите «Принимать ответы», сохраните.
4. Скопируйте ссылку `https://<сайт>/f/disco-new-year` и отправьте в чат классов.
5. Ответы — на странице «Ответы», выгрузка в Excel — кнопка «Скачать CSV».
6. Можно задать автозакрытие по дате и максимум ответов.

Данные о школе (адрес, ссылки на ВК) — в `src/lib/site.ts`.
